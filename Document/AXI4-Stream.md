# AXI4-Stream 接口与通信协议说明

## 1. 协议概述
AXI4-Stream (Advanced eXtensible Interface 4 - Stream) 是 ARM AMBA 4 规范中的一种用于高速数据流传输的点对点协议。它与内存映射的 AXI4（读写地址和数据）不同，**AXI4-Stream 没有地址通道，不使用地址进行读写，而是专门用于主设备 (Master) 与从设备 (Slave) 之间的纯数据流单向突发高速通信**。

在我们的 `EDM_Monitor` 项目中，AXI4-Stream 接口贯穿了整个核心数据通路（从 ADC 到 FIFO，FIR 滤波，功率计算，滑动窗口能量计算），以及最终打包上报 DMA 的通道。

---

## 2. 接口端口信号说明

AXI4-Stream 拥有极其精简且高效的信号线。在我们的项目中，主要用到了以下核心端口：

| 信号名 (常见的后缀格式) | 方向 | 描述 | 协议关键物理意义 |
| :--- | :---: | :--- | :--- |
| **`ACLK`** | 输入 | 主时钟。所有 AXI4-Stream 信号均在此上升沿更新和采样。 | 同步基准。 |
| **`ARESETn`** | 输入 | 低电平有效的同步复位信号。 | 确保所有握手标志的初始一致性。 |
| **`TVALID`**<br>(必选) | Master -> Slave | 主机发送数据有效指示（**Valid**）。 | Master 告诉 Slave：“我线上给出的 `TDATA` 现在是真实有效的，请接收。” |
| **`TREADY`**<br>(可选) | Slave -> Master | 从机接收准备就绪指示（**Ready**）。 | Slave 告诉 Master：“我现在的缓冲区或计算流水线是空的/能干活的，可以接受新数据。” |
| **`TDATA`**<br>(必选) | Master -> Slave | 数据总线（**Data**）。常见宽度如 8, 16, 32, 128 等。 | 主传输负载。只有在握手成功时才允许读取或覆写。 |
| **`TLAST`**<br>(可选) | Master -> Slave | 帧边界指示 / 最后一个词指示（**Last**）。 | “这一波总线上连续的数据包到此结束。我是这次包（Frame）里的最后一个数据尾巴。” |
| **`TSTRB` / `TKEEP`**<br>(可选) | Master -> Slave | 字节有效掩码控制（Strobe/Keep）。 | 用于表明 `TDATA` 中哪些 Byte 是有效字节，在非定宽传输中会用到（项目中未用，因为全为满载定宽）。 |

## 3. 基本传输时序：握手机制

AXI4-Stream 的核心灵魂是双向握手协议：**只有在相同时钟的上升沿，`TVALID` 和 `TREADY` 同时为高电平时（`TVALID & TREADY == 1`），一次数据传输（Handshake/Beat）才真正发生，数据 `TDATA` 才被从机吃下。**

这构建了完美的双向弹性流水线（**背压机制** Back-pressure）：
1. **Master 未准备好**：`TVALID` 保持 0。无论 Slave 多么渴望数据 (`TREADY`=1)，都不会发生传送。
2. **Slave 未准备好**：`TREADY` 保持 0。即便是 Master 有急迫传不完的数据 (`TVALID`=1)，Master 也不被允许丢弃旧数据换新，必须把那个数据锁在总线上死等。这被称为“背压”。
3. **同时准备好**：两者都拉高。时钟到来时数据完成单拍跃升（被拿走），下一拍可以清零或者立刻给下一个连续的新数据（连续突发传输 Pipeline Burst）。

### 时序波形示例
```text
           ___     ___     ___     ___     ___     ___     ___
ACLK    __|   |___|   |___|   |___|   |___|   |___|   |___|   |__
               _______ _______________________ __________________
TVALID  ______|       |                       |
                       _______________                 __________
TREADY  ______________|               |_______________|
                       _______         _______ _______
TDATA   --------------<__D1___>-------<__D2___X__D3___>----------
                      (Wait D1 )      (Beat 2) (Beat 3)
```
* **周期 2**：`TVALID`=1，但 `TREADY`=0，数据 D1 被压在总线上。握手未成功。
* **周期 3**：`TREADY` 在这个周期上升。两者同时为 1！握手成功！**D1 传输完成**。
* **周期 4**：`TVALID` 下降，尽管 `TREADY`=1，总线空闲，无数据传。
* **周期 5/6**：两者连续两拍均为 1，**D2、D3 实现无缝的高速流水传输**。

## 4. 背压机制 (Back-Pressure) 深度解析

**背压（Back-Pressure）** 是 AXI4-Stream 协议中最具威力也最重要的特性之一。它指的是**下游（接收端）反向控制上游（发送端）数据发送速率的能力**。

### 4.1 为什么需要背压？
在复杂的数字信号处理（DSP）或数据流转系统中，各个模块的处理速度往往并不均衡，或者如 Zynq PS 端 DMA 等目的端由于 DDR 总线竞争可能会暂时无法接收数据。如果没有背压机制，上游高速模块（如一直在全速运转的 ADC 或封包模块）如果一味强行输出，下游的 FIFO 或处理流水线就会被迅速打爆，导致**致命的数据覆盖与丢失**。

### 4.2 背压的具体执行过程
背压功能的实现完全依赖于从机（Slave）对 `TREADY` 信号的控制：
1. **施加背压 (TREADY = 0)**：当 Slave 评估发现自身的内部缓冲（如 FIFO 的 `Almost Full`）快满了，或者计算模块正在处理关键算子无法接纳新词时，会主动拉低 `TREADY`。
2. **上游锁存死等 (Hold State)**：此时，不管前方的 Master 在业务上多么急切地想扔出当前数据（`TVALID = 1`），根据 AXI 流协议的铁面规定：只要没握手成功，Master **决不允许**主动撤回 `TVALID` 信号，也**绝不允许**将线上的 `TDATA` 偷换为下一个数据！它必须死死卡住这些总线状态，原地等待。
3. **撤销背压 (TREADY = 1)**：当 Slave 从阻塞中恢复或腾出了至少 1 Word 的空间，立刻重新拉高 `TREADY`。此时停滞在总线上的数据在紧接着的下一个时钟周期被从机成功吃掉，整条数字通道又再次恢复顺畅流动。

### 4.3 协议中防范背压死锁的“铁律”
如果有这样一种荒唐的设计：“发送方想等接收方准备好（TREADY=1）再宣告自己有效（TVALID=1），而接收方又非要等发送方有效了才准备好。”——通道将彻底卡死！因此 AXI4 协议有着非对称的设计禁忌：
- **发送禁止试探**：Master 只要自己手头有了有效数据，必须单方面立刻拉高 `TVALID`，**绝对禁止**等待 `TREADY` 为高之后才做出置位动作。
- **接收从容灵活**：Slave 则拥有极大自由度。它可以常态拉高 `TREADY` 表示空闲门禁常开；也可以任性拉低，直到它观察到线上 `TVALID` 变高之后，再去慢悠悠拉高 `TREADY` 进行吸纳。

## 5. 主机（Master）与从机（Slave）角色

* **Master（数据源，发送方）**：主动拉高 `TVALID` 并推送出有效的数据和 `TLAST`。它**绝不能**看到 `TREADY` 变 1 之后才去拉高自身的 `TVALID`（这叫握手死锁！协议严禁 `TVALID` 依赖 `TREADY` 发生翻转）。一旦 Master 发出了 `TVALID`，直到 Slave 吃下数据（`TREADY` 变高响应）前，不允许 Master 再把它拉回成 0。
* **Slave（数据宿，接收方）**：通过拉高或拉低 `TREADY`，从机控制着流水线的真实流速。Slave **可以**依赖 `TVALID` 为 1 之后再拉高自己的 `TREADY`（按需开启吸水模式），当然如果是永不堵塞的状态（例如我们的 `slide_window` 在持续接收数据），直接将其绑死常高 `1'b1` 也是允许的。

## 6. 项目中的实际应用场景

在我们的 `EDM_Monitor` 中有着众多绝佳的高速背压与流水线实例：

1. **`axis_data_fifo` -> PS 端 AXI DMA**：这里的数据是一次发一整个报文（带有最后结尾的一拍 `tlast` 拉高向 DMA 宣告一个放电事件包传输完成）。为了防止由于 PS 端内存没开好导致的包丢失，FIFO 作为庞大的缓存，利用 `tready` 紧紧背压住前面的封包核心；
2. **`slide_window` 中对数据截断**：内部写死了 `s_axis_tready = 1'b1;`。这是因为我们希望前端的 FIR 滤波器永远不要被堵塞停顿。不管放电状态（`enable`）激活与否，窗口总是全吞吐流经的数据，只是在其未使能时内部移位管不发生记录罢了。这通过一种物理不背压的巧妙手段保证了时序延迟的计算绝对对齐。
3. **有效性传递（Valid Pipeline）**：在 `pow_calc` 和 `FIR_Filter` 的运算中，有效信号并不是一直拉高的。当这级模块收到握手（`fire = tvalid & tready`），它才在内部经过 N 拍潜伏期流水计算后，在输出端把它自己的 `m_axis_tvalid` 高电平传递出去。
